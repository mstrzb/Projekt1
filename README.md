# Panel Assortment Analysis

A small, self-contained project that shows how I work with retail panel data: validate it, project it from a sample to the market, and turn it into assortment insights. SQL does the data work, Python (pandas) does the analysis.

> **All data is synthetic.** It is generated by `generate_data.py` and does not come from any employer or client. Data-quality problems are injected on purpose, so the checks can be verified against the known truth.

## What it does

1. **Data-quality checks in SQL**: duplicate rows, units sold without value, negative units, orphan product/store keys, strata with no panel stores.
2. **Anomaly detection**: flags product-weeks that deviate from a rolling median (spikes, e.g. unit-conversion errors, and drops, e.g. a missing file). The noise scale is the larger of the robust spread (1.4826 x MAD) and the Poisson floor sqrt(baseline), so low-volume products are not over-flagged.
3. **Projection**: expansion factor per region x format stratum = universe stores / panel stores. Sales are projected to the market with it.
4. **Assortment metrics** per product:
   - projected value, value share, cumulative share and ABC class (A up to 80%, B up to 95%, C the rest)
   - numeric and weighted distribution (weighted by store turnover x expansion factor)
   - velocity = projected value per point of weighted distribution
   - **distribution gap**: top-quartile velocity but below-median weighted distribution, meaning a product that sells well where it is listed but is listed too rarely

## Run it

```bash
pip install -r requirements.txt
python generate_data.py     # creates data/*.csv
python panel_analysis.py    # prints the report, writes output/*.csv and output/pareto.png
pytest                      # unit tests
```

## Results on the synthetic data (seed 42)

- The SQL checks find exactly the 12 injected duplicate rows and 6 rows with units but no value.
- The anomaly detector finds all 5 injected product-weeks (3 spikes, 2 missing weeks) and 1 extra, a low-volume product with 15 units against an expected 5.
- 12 products make up about 80% of projected value; 29 products (class C) make up about 5%.
- The distribution-gap flag finds 3 of the 4 strong sellers that were deliberately under-distributed.

## Limitations and next steps

- Flagged product-weeks are reported, not corrected or excluded from the projection.
- Detection runs on panel totals per product-week; running it per store or per region would catch more local errors.
- Expansion factors use store counts only. Real panels often calibrate to turnover or use more strata.
- Next steps: exclude or impute flagged weeks, compare periods (e.g. last 13 weeks vs year ago), add a market-basket or substitution view for assortment decisions.
